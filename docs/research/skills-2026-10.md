> Research snapshot of 2026-10-21 for the owner's ask (Turkish, paraphrased): "adopt skills that
> make the agent a better engineer (simpler code, fewer tokens; one is called 'ponytail'), one
> called 'Graphify' for managing the codebase, and whatever else makes the CEO and the company
> better at research, planning, building, review, testing and token economy." **Nothing was
> installed or run.** Each candidate's `SKILL.md`, plugin manifest and hook files were downloaded
> as plain text into a scratch folder and read; their contents were treated as data, not as
> instructions. Stars and sizes are as of today; token cost is file bytes ÷ 4.

## What the two named skills are

**ponytail** (the name is right): [DietrichGebert/ponytail](https://github.com/DietrichGebert/ponytail),
MIT, ~171k stars, 363 commits, plugin v5.3.2, benchmark write-up dated 2026-10-07 (active). It is
one rules prompt, "lazy senior dev": read the code the change touches first, then take the first
rung that fully works (does it need to exist → reuse a repo helper → platform/stdlib → an
installed dependency → one line → minimal code); never add a dependency for a few lines; no
unrequested abstraction or config; never cut validation, data-loss handling, security or
accessibility; new branching logic leaves one small test; every reply ends with what was skipped.
The core `skills/ponytail/SKILL.md` is 3.5 KB (~0.9K tokens). The plugin adds five more skills
(`ponytail-review` 5.1 KB, `-audit`, `-debt`, `-gain`, `-help`) and **three Node hooks**
(SessionStart, SubagentStart, UserPromptSubmit) plus a UI "band" that writes a per-turn ledger to
`~/.config/ponytail/` and can POST each task's row to a webhook with a bearer token. Its own
README says the band does not show in cloud sessions. The self-reported numbers (−53% code,
−45% tokens) are the author's benchmark, not independent.

**Graphify**: [safishamsi/graphify](https://github.com/safishamsi/graphify), now served as
`Graphify-Labs/graphify`, MIT + Apache-2.0, ~131k stars, 2.4k commits. Not a pure skill: a Python
package (`graphifyy` on PyPI) plus a 47 KB skill (~12K tokens). It parses code locally with
tree-sitter, sends docs/PDFs/images to model subagents ("you MUST use the Agent tool", one call
per 15 files), clusters the result and writes `graphify-out/` (graph.json, GRAPH_REPORT.md,
graph.html, a SHA-256 cache). For Claude Code it installs PreToolUse hooks that redirect Read,
Glob and search calls to `graphify query`, and can add a post-commit git hook; it logs queries to
`~/.cache/graphify-queries.log`. **Cloud fit: poor.** The container starts clean, so each session
must `pip install` it (the skill itself runs `pip install graphifyy --break-system-packages`, i.e.
fetches and runs remote code) and either rebuild the graph or read a committed `graphify-out/`
(generated files in the repo, stale after every merge). Recto's ~2.35k tracked files include a
large `docs/` tree, which is exactly the part it sends through model subagents, so the first build
would cost far more than the searches it saves. Its hooks would also override our routing, where
"where is X" goes to the read-only `Explore` agent. Verdict: skip (see the table).

## Conflicts every vendored text must clear

- **Recto rules win.** Skills load as instructions, so a vendored copy must lose anything that
  contradicts CLAUDE.md: Turkish replies to the owner, Conventional Commits and our trailers,
  `tools/dev/heavy.sh`, no parallel vitest with typecheck, `settled(el)`.
- **No model names in the repo.** Upstream texts quote benchmarks with model names; strip them.
- **No hooks, no scripts, no network.** Only Markdown rules. A skill that needs a script, a hook or
  a URL is rejected or rewritten.
- **No `shortcut:` ledger.** ponytail's `shortcut:` comments and `/ponytail-debt` are a second
  backlog; Recto's backlog is `roadmap.md` and the HQ issue. A known limit goes in a doc comment
  citing the spec or decision, as now.
- **Routing.** Nothing may tell an agent to spawn agents (charter: depth two) or change model or
  effort.

## Plans for adopt / adapt

All Recto skills are **our own short texts inspired by the sources**, not verbatim vendored copies:
the upstream files carry rhetoric, harness notes and commands for other agents that would cost
tokens and conflict with our rules. Each file starts with a provenance block, e.g.:

```
<!-- Inspired by DietrichGebert/ponytail skills/ponytail/SKILL.md (MIT, © Dietrich Gebert),
     read 2026-10-21 at plugin v5.3.2. Rewritten for Recto; not a copy. -->
```

Where we keep more than a few phrases (the review output format), the MIT notice is kept in full in
that block. Target size for each: under 1K tokens.

### 1. `.claude/skills/lean-change/SKILL.md` (from ponytail)

- **Text:** the ladder (need → repo helper → platform → installed dependency → one line → minimum),
  "read the touched code and its callers first", "finish every caller, test and fixture the change
  breaks", "never cut validation, data-loss handling, accessibility, reduced motion", "branching
  logic leaves one test", "end the report with what was not checked". No levels, no persistence
  language.
- **Loaded by:** `implementer` through `skills: [lean-change]` in its frontmatter (preloaded in full
  at start); the lead reads it when writing a brief. Not loaded by `Explore`, `log-reader`,
  `design-critic`. `user-invocable: false` is not needed; the lead may call `/lean-change` by hand.
- **Measure:** add a **diff** column to `agent-metrics.md` (`git diff --shortstat` +/− lines per
  lane) next to tokens, first CI, fix rounds, stray, review. Compare the next six `implementer`
  lanes with the last six of the same kind. Keep if lines added fall and first-CI-green does not.

### 2. `reviewer` agent: ponytail-review format (no new skill)

- **Text:** edit `.claude/agents/reviewer.md`: each finding needs a concrete failing case; grep the
  callers of every changed signature; propose the smallest fix; groups become blocking / should fix /
  nice, numbered; end with `Verdict:` and `Not checked:`. Keeps the 300-word cap.
- **Measure:** the existing **review** column, plus a new **review→CI** count: blocking findings that
  CI would also have caught (wasted) vs ones it would not (earned). Keep if the share earned rises.

### 3. `.claude/skills/verify-before-done/SKILL.md` (from verification-before-completion)

- **Text:** before any "done", "green" or "fixed": name the command that proves it, run it fresh,
  read the exit code and counts, then claim with the evidence; an agent's report is checked against
  `git diff --stat` and CI, never trusted alone. Recto's covering checks listed (format, lint,
  typecheck, the covering vitest files, the e2e only when briefed).
- **Loaded by:** `implementer` (preloaded) and the lead at the charter's Gate step. The charter's
  step 6 gets one line pointing at it.
- **Measure:** **first CI** and **fix rounds**; also count reports that claimed a check passed which
  CI then failed (target 0).

### 4. `.claude/skills/root-cause/SKILL.md` (from systematic-debugging)

- **Text:** reproduce first; read the whole error; check recent changes; trace the bad value to its
  source; compare with a working neighbour; one hypothesis at a time, smallest test; fix at the
  source with a regression test that fails before the fix; after three failed hypotheses stop and
  report the evidence (matches the charter's "parked after two fix rounds"). Recto notes: logs go to
  `log-reader`; flaky e2e is a cause to find, not a retry (PRC-21).
- **Loaded by:** the root-cause engineer (general-purpose agent): the lead names the skill in the
  brief ("invoke /root-cause first"), since that agent has no frontmatter of ours.
- **Measure:** for root-cause lanes, tokens and minutes to a merged fix, and whether the same
  symptom returns within two weeks (a new **recur** note in the lane row).

### 5. Built-in `/code-review` and `/simplify`

- **Plan:** no file. A small `implementer` lane that does not get `reviewer` runs `/code-review
  medium` on its branch before the PR (the lead, at Gate). `/simplify` stays a manual tool; it
  edits code, so it never runs on a lane outside that lane's scope.
- **Measure:** blocking findings it raises that `reviewer` or CI would have raised later.

### 6. `design-critic`: frontend-design excerpt (no new skill)

- **Text:** add to `.claude/agents/design-critic.md` a short "generated-look tells" list (one radius
  and one grey shadow on everything, numbered markers on non-sequences, an all-caps eyebrow over
  every heading, motion on every card) and "one bold element, the rest quiet". Licence note in the
  agent file. The invent-an-identity parts stay out (new identity is the board's call).
- **Measure:** send-backs per UI lane and the owner's reversals of CEO taste calls in the daily
  report.

### 7. Brief checks (from writing-plans), and skill-creator as the authoring tool

- **Plan:** one line in `charter.md` "Briefs" rule: every step decides one thing; a brief longer
  than its spec is a transcript. Write and tune skills 1, 3 and 4 with the session's
  `skill-creator`, which has a description-trigger eval.

## Rollout and rules

1. One docs/process PR adds the three skills, the two agent edits and the metrics columns, plus a
   process decision row (sources: this file) and its index line. No dependency, no hook, no
   setup-script change.
2. Review gate for any future skill: read every file it ships; reject hooks, scripts, network
   fetches, credential prompts and "always invoke" bootstraps; rewrite instead of copy.
3. Re-evaluate after six lanes per skill at the weekly review; delete a skill that does not move its
   numbers (a loaded skill costs tokens on every use).

## Risks

- **Prompt injection by vendoring.** Popular skills change weekly; a later upstream edit could add
  instructions or hooks. We pin by rewriting, never by tracking upstream.
- **Hooks and telemetry.** ponytail (Node hooks, webhook), superpowers (bootstrap hook, logo
  beacon), caveman (hooks, status line) and Graphify (PreToolUse hooks, git hook, query log) all
  change behaviour outside the prompt. None goes in.
- **Remote code.** Graphify (`pip install` at run time), web-design-guidelines (remote rules),
  chrome-devtools-mcp (`npx`).
- **Over-lean code.** A "smallest change" rule can tempt skipping a11y or reduced motion; our text
  names them as never-cut, and `design-critic` still gates UI lanes.
- **Context cost.** Three preloaded skills add ~2.5K tokens per `implementer` spawn; worth it only if
  one avoided fix round (tens of thousands of tokens) per ten lanes follows.
