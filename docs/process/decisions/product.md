| PF-18 | **A closed document's source is parked, and the engine worker ends when none is open.** Closing a tab is undoable, so history keeps the source; it used to stay open in the PDFium worker with its bitmaps, and a wasm heap never shrinks while its worker lives (R25 memory baseline: +1,257 MB above Home after three open/close cycles). | PRD-23 | **The palette reads a query with a rule grammar, not a model (R25 Epic 4, R12 E10 phases 1-2).** `commands/query.ts` is pure: `parseQuery(query, {pageCount, currentPage, headings, recents})` returns one typed intent or null (null: rank commands as before). The query is folded as the fuzzy matcher folds it (`foldForSearch`: Turkish-aware case folding, no diacritics, so `SİL`, `SIL`, `sil` agree), number suffixes (`7'ye`) and ordinals (`4.`) are dropped, Turkish page words match by stem (`sayfa*`). A phrase is accepted only when every word is understood, so `delete annotation` stays with the command list. Intents, in priority order: page jump (`120`, `p 120`, `sayfa 120`), page-range action (rotate, delete, duplicate, extract over `3-7`, lists, `even/odd` = `çift/tek`, `all`, `first/last N`, `this page`; rotate takes right/left/180), open a recent file (`open <name>`, `aç <ad>`), heading jump (`go to <text>`, `<text> git`). Every acting intent carries the resolved, ascending pages (`pages`, `pagesLabel`) and the command id, so the palette shows them before anything runs; an impossible phrase returns `invalid` with a reason (`no-document`, `out-of-range`, `reversed-range`, `no-pages`, `all-pages`; a delete of every page is refused). *Score floor* (`fuzzy.ts` `isMeaningfulMatch`): after the first character, each matched character must follow its predecessor or start a word, with one orphan allowed per three characters; so `print` no longer finds `Toggle pen draws in Edit` while `zi`, `tl`, `zom in` still land. *Synonyms* are catalog keywords only on commands that exist (compress: `make smaller`, `shrink`, `küçült`; Save a copy: `save as`, `farklı kaydet`; dark mode, OCR, split, and the like); there is no print command until Epic 5, so `print` finds nothing. | PRD-26 | **A launch whose edition chunk fails is retried in the page, then reloaded once, then explained; never a blank page.** `main.tsx` loads the edition through `pwa/boot-reload.ts`. (1) When `import('./app')` (or the compact edition's) rejects, any stylesheet that failed is asked for again under `?r=<time>`, then the edition's chunk itself, its file and export key written into the entry at build by `recto:edition-chunks` (vite.config.ts), which fails the build when either chunk is missing. The retry is safe because each edition chunk is a facade of its module alone that no other chunk imports: the `codeSplitting` group `editionGroups` moves what the edition dominates and reaches statically into `editor` / `compact-core`, and what both editions reach into `editions`; `tools/qa/bundle-budget.ts` fails when any chunk imports `app-*` or `CompactApp-*`. Measured (gzip): editor initial 832.4 to 830.4 KB, compact 279.5 to 284.8 KB, first paint 74.4 to 73.9 KB: the screen and the retry stay in the entry, and what follows the service worker's registration (status, update checks, warming the wasm: `pwa/service-worker.ts`) loads after the first paint instead. (2) When that fails too, the page reloads once, after its `load` event, the time in `sessionStorage` (`pdf-editor:boot-reload:v1`). (3) A second failure within 60 s, or no session storage, shows a static screen outside React (its two lines, EN and TR, kept in `boot-reload.ts`: message modules would cost the first paint more than the text) whose Reload loads the address with `_r=<time>` added. Engines: a module that failed keeps failing under its own URL; WebKit (the iPad) hands the failure to the reloaded page too, so there only the in-page retry recovers the edition chunk, and a failed shared chunk (react, i18n, motion, `editions`) ends on the screen, whose Reload does not recover it either (WebKit fails the chunk again on the `_r` page): a known Safari gap, for the owner; Chromium and Firefox recover those by the reload. Offline: the service worker ignores `r` (`ignoreURLParametersMatching`), so the retry is answered by the precache; the cost is that a retry cannot reach past a bad precached copy, which the cache-busted document reload (`_r`, a navigation) and the worker's update flow handle. Cause: in CI (Chromium, `e2e-office`) the reload after Settings removed the Office package (PRD-21) sometimes had a few of the app chunk's module requests, answered by the service worker from the precache, end `net::ERR_ABORTED`; the import rejected and the page stayed blank, while a fresh load booted.
