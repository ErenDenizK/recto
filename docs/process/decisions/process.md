| PRC-16 | **The UI face's preload matches the engine's font fetch mode, so every engine fetches the file once.** Chromium and Firefox fetch an `@font-face` file in CORS mode and need `crossorigin` on its preload; WebKit fetches a same-origin one in no-cors mode (WebKit bugs 230492, 86817), so a `crossorigin` preload goes unused and Safari fetched the 70 KB Latin file twice. A static link cannot serve both, so `public/preload-face.js`, a classic script in the head of `index.html` and `about/index.html` (the CSP allows no inline script; the file names come from its `data-href`), adds the preload with `crossorigin` everywhere but WebKit. WebKit is told apart by `navigator.vendor` ("Apple Computer, Inc."), which HTML freezes per engine and no user-agent override changes; no feature reveals a fetch mode, and a proxy feature such as `GestureEvent` is missing from the Linux WebKit CI runs. The fetch starts when the script runs, one small cached request after the HTML, still well before the shell needs the face; the script is outside the first-paint JS gate (`public/`, not `assets/`). `fonts.spec.ts` checks the preload's mode per engine; if WebKit moves its font fetches to CORS mode, its count there fails and this row is revisited. | 2026-10-12 | Implementer (R16 lane H); CI WebKit, 2 unconditional GETs at the counting proxy (PRC-15) | In force |
